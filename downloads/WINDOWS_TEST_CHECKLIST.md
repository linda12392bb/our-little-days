# Windows API 與語音試用版實測清單

Phase 1 已由使用者回報 Windows 11 開啟 EXE、十三名單與氣泡顯示、Chrome 擷取預覽及 6 秒間隔成功。下面都是 **新版待驗收項目**，不能用 Phase 1 結果替代。

使用者也已回報單次畫面分析與所選角色回覆成功，Yeti X 收音及辨識文字可出現。以下完整清單供開發驗收，**升級 0.4.3 不要求重做已成功的成本測試**。這次先確認版本 0.4.3，勾文字 AI，在一般聊天輸入一次「晚安」：應直接顯示正常回覆，文字 AI 維持勾選。安靜模式已勾選也不需關閉，應優先回覆使用者；跨批角色接話仍需逐步實機觀察。

1. 備份舊公寓，關閉舊版，解壓新 ZIP，啟動。舊聊天／角色／關係仍在，麥克風、AI 及擷取都關閉。
2. 尚未輸入 Key 時，打字／停留十分鐘。聊天保存，API 請求數為零。
3. 本機設定 Key、核對價格與 NT$500 月預算。只保存設定，請求數仍零；金鑰檔是加密 DPAPI，角色檔／SQLite／日誌無明文。
4. 指定 Chrome，開始 6 秒擷取。預覽正確，不傳桌面或其他視窗。
5. 單次畫面分析：記錄模型、輸入／輸出 token、NT$估算與平台帳單。單次角色回覆：同樣記錄。成功前不能啟用自主陪伴。
6. 調低月預算到低於已用額度（或不足下一次預留），再按測試。必須被攔截，請求數不增加；恢復原預算。
7. 啟用文字 AI，送出一次訊息。只增加一次請求，少數住戶自然發言。找出至少一次角色→角色接話，確認箭頭及重開後關聯保存。
8. 啟用自主陪伴，完全不打字，改變 Chrome 大部分內容並停留兩輪擷取。新事件應可引發角色發言或自然安靜。畫面不變的十分鐘，除初次觀察外請求數不持續增加；十小時靜態測試可另安排。
9. 時鐘／游標小變動不應觸發反覆付費；若動畫／小範圍文字漏判，回報情境與請求數供調整。返回同一事件不應反覆評論。
10. 洛陽固定日文、REO 全敬語、RIXO 不良自稱俺、序關西腔／調戲♡；每段外語發言與敘事立即有繁中翻譯。光、聖護原人格不改，聖護各 AU 不混線。此項是模型實際品質驗收，不能只靠 JSON 設定宣布通過。
11. 按「暫停所有 AI」。擷取可繼續，但新畫面／文字不再觸發付費，既有聊天與記憶保留。
12. 請求進行中按擷取暫停／停止。擷取停止、AI 取消、晚到訊息不追加；可能費用記為待確認。不能保證平台取消已收到的計費。
13. 正常關閉重開：聊天、接話、重要事件、長期記憶、用量與預算恢復；AI 與麥克風不自動啟用。
14. 儲存測試事件／記憶，另備份公寓與用量。還原舊公寓：原資料安全副本在 backups；用量不倒退。合併還原用量：不重複計算、不移除較新的請求。
15. 模擬斷網／無效 Key。一次失敗後停止 AI，不自動重試。待確認費用可保守保留，需與平台核對。
16. 請求進行中用工作管理員結束程式，再開啟：已提交聊天仍在，未完整提交的多人訊息不留半套；in-flight 費用保留，AI 關閉。

請回報兩項成本測試的用量與估算、實際模型名稱、安靜時請求數是否增加，以及一段已翻譯的角色互相接話。**不要附上 API Key。**

語音新增驗收：請另依 [VOICE_INPUT.md](VOICE_INPUT.md) 的九項清單測小聲／短句、安靜、耳機背景播放、預覽取消、文字保存、重開及異常中斷。尚未宣稱實機通過。
