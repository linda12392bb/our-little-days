# 安靜自主聊天與連續接話 · 0.4.12

沿用 Windows 公寓、完整十三份人格與原 SQLite。使用者不說話、不打字，住戶也可以自行開話題、彼此接話；不需持續擷取視窗。每次啟動此功能與文字 AI 都關閉，必須自行勾選。

「安靜」是程式自行判斷的空閒條件，不需要使用者先判斷自己是否安靜。每次啟動後勾選一次，即可保持開啟；在公寓打字、說話、辨識語音或已有待處理回覆時延後閒聊，空閒後再依冷卻、去重和額度檢查。開始說話時不用手動關閉安靜開關。

## 0.4.12：HARU 方言與作品名稱辨識

HARU 的本輪確認是不使用關西腔。角色檔只在 language_rules 加入標準日文方言及明確語體；原 source_text、母語、敘事、人格核心、溫柔／明亮／直接的反應、稱呼、外貌、關係均保留。舊 SQLite 啟動時先安全備份，一次性套用這兩條語言規則；之後重開不覆蓋後續自訂。序仍維持原關西腔與調戲、♡。

多人生成給 HARU 自己的標準日文分支，不沿用序的方言或思考方式；保存前檢查已識別的關西句型。清楚引用別人的台詞不當成本人方言，「めっちゃ」「たいへん」「やなぎ」等不一律封鎖。不機械改字尾、不擅改原人格、不另外付費修稿。違規整批不寫聊天，費用照實記錄，一般文字／語音 AI 仍可繼續；自主批次只停該自主功能。

本機作品索引提供《螢火蟲的出嫁》／《螢火之嫁》／《ホタルの嫁入り》的同作名稱、橘オレコ與漫畫類型，明確區分《螢火蟲之墓》／《火垂るの墓》。這是少量內建作品基本資料，**中日作品、作者及漫畫類型已由使用者確認；目前未進行外部即時查核**，不包含未核對劇情或最新改編進度；不是全部作品百科，也不是目前畫面辨識的保證。未收錄名稱不表示不存在，不應改成相近作品或說成使用者自創。

已保存的使用者訊息提到已收錄作品時，在本機先精確對照再交給原本那一次 API；各住戶共用同一作品身分，仍保有各自人格。後續問「這部的作者／主角呢」可以沿用本世界線作品焦點；焦點與角色人格、重要事件及長期記憶分開，重開與備份保留，清空本世界線聊天時才移除其訊息衍生焦點。未保存的語音只在本輪對照，不永久保存原語音文字或更新焦點。

可免費確認：在右側任一住戶的「查看這位住戶的設定」→ **作品對照（與人格分開）**，看到最近提及的中日名称、作者與類型。此頁不用 Key、不呼叫 API、不查詢外部網站。HARU 的「目前套用設定」應顯示標準日文、不使用關西腔；原始後台另頁保留。無需重做已成功的成本測試。

同批最多十三位仍共用一次 API、2000 輸出 tokens，完整十三人格照常送出；沒有背景付費搜尋、付款或儲值。只改 HARU 的已確認語言規則，其他十二角色檔位元組不變。更新確認底部 0.4.12，再自行勾選原 AI 開關。

本機／模擬檢查能證明上述句型攔截、對照與保存機制，**新版 Windows 實機、正式模型的自然度及全面作品／畫面識別仍待驗收**；有限檢查可能漏判或誤判。

## 0.4.11：聖護生成與保存前的語體檢查

0.4.10 截圖中聖護仍說「指していますか？」；舊提示只能偵測，仍會將敬語保存成正式發言，前幾次生成指引沒有達到要求。本次移除生成欄位中完整的敬語錯誤示範；聖護自己的 schema 分支先選常體表達目的，再由自己的觀察、判斷與本輪情境生成完整台詞及繁中翻譯。這不是刪掉字尾或套固定回話。表達目的只是短格式標記，不輸出思考過程、不新增人格或互動記憶。

新 API 結果寫入聊天前再檢查聖護的常見直接敬語及混用愛稱；未通過時整批不寫入，避免半批接話鏈破損。原始台詞不改寫、不偷偷付費修稿或重試；費用照實結算。「最近回覆檢查」與「最近 API 結果」可免費查看攔截理由與實際用量，沒有保存違規原回應副本。文字／語音 AI 保持可用，下一句已送出的使用者輸入仍會處理；自主批次違規只暫停該自主功能。

舊聊天仍保留，不回頭刪除、改寫或重新標記已回覆。十三份角色檔、聖護第一季原人格／月／僕／柔和而有壞心眼／各 AU、原始後台、長期記憶及關係均不修改。REO 的敬語不受此檢查限制，清楚標成引用的他人台詞也不當成聖護自己的敬語。

每批仍只用一次 API、最多十三位、共用 2000 輸出 tokens。所有費用仍共用既有日額與月額，沒有更換模型、付款或儲值操作。更新後確認底部 0.4.11，再手動勾原 AI 開關；不用重輸 Key、下载模型或重做付費成本測試。

本機模擬驗證可證明已知句型會攔截、排隊輸入與原資料保留，不能證明正式模型一定生成符合第一季人格的好台詞。**檢查可能漏判或誤判；新版 Windows 實機及正式模型的思考、節奏與口吻尚未驗收。** 沒有提示也不等於完整人格通過。

## 0.4.10：住戶自行開話題、互相接話

妳已勾選安靜聊天仍只有角色對妳說話，本次修正自主對話與一般回覆的分流。安靜群聊及新的畫面事件自主討論以其他住戶為說話對象，可由一位先開題，其他人同批接話，也可隔一批回嘴。舊使用者訊息仍完整保留作背景，不當作每批的新提問。近期住戶之間的真實訊息編號與對象會另列給模型，延續原 SQLite 接話鏈；沒有固定光、序、REO 每次出場。

妳打字或說話時仍優先處理當下輸入，閒聊延後，不需要手動切換安靜／聊天。每 3 分鐘是本機檢查，不是定時付費請求；原自訂冷卻、日額及共用月預算沿用。同批最多十三位共用 2000 輸出 tokens，沒有增加自動重試、摘要或付費修稿。如果自主批次只有對使用者說話或對自己說話，本機不把它假標成角色接話；保留實際費用、暫停該自主功能並提示，一般文字／語音回覆仍可繼續。

更新後確認底部 0.4.10，再勾「啟用文字 AI 回覆」與「啟用安靜時住戶自行聊天」。啟動預設關閉是原有設計；不需重輸 Key、下載語音模型或重做已成功的付費測試。可以不擷取畫面，正常使用時看氣泡箭頭是否指向其他住戶，及後續批次能否接續前面的話題。人格／原始後台／聖護最新規則／關係／聊天與記憶沒有修改。

開發端使用本機模擬 API 測試了「光向序開題→下一批序回覆光的真實訊息→REO 接序」與使用者中途輸入的優先處理。這證明排程、分流與保存機制；**新版 Windows 實機與正式模型的自然接話品質尚待觀察**，不能保證每批一定發言。

## 排程與優先順序

- **每 3 分鐘只在本機檢查**，沒有檢查用的 API 請求。檢查時先看是否啟用、正在說話／辨識／編輯文字、待送語音、住戶忙碌、待處理畫面變化、冷卻與額度。
- 預設冷卻 **6 分鐘**，可在 API 安全設定改為 3–30 分鐘。開啟功能後先等待冷卻；對話／畫面分析完成、你開始打字或本機偵測到說話，都會延後下一批。暫停、關閉或預算不足不會產生新付費工作。
- 正在輸入、說話或有待處理文字時不插入閒聊。已啟用畫面自主分析且有新的畫面候選時，優先處理畫面。已送出的請求無法保證撤銷或免計費；當前批次完成後優先處理你的待回覆訊息，不啟動平行請求。
- 每批共用 **一次 API 請求、最大 2000 個輸出 tokens**，涵蓋所有角色的母語、敘事、逐段繁中翻譯與 JSON 格式。通常 2–3 則短訊息，情境需要時最多十三位同批參與；人數較多時每人更短，不要求十三人全出場。輸出上限可以降低，不能超過 2000，太低可能造成格式／翻譯截斷並停止 AI。
- 不固定消耗 2000 tokens，以 API 回報用量結算。輸入仍含完整十三人格、當前世界線記憶與聊天，沒有節費刪減人格。
- 本機會擋掉與最近安靜批次相同的整批發言。模型選擇安靜或產生重複內容，本次請求仍計費，但不再次顯示同一批；冷卻逐步延長至最多 30 分鐘。沒有背景即時思考 API，也不自動重試。

## 保留角色之間的連續性

每次送入當前世界線近期 60 則聊天，並額外載入保存在 SQLite `settings` 的 `conversation:<世界線>` 獨立結構：接話原文的訊息 ID、參與者、最後發言、近期批次指紋、冷卻與安靜次數。保留起始四則及後續最近 36 則作為接話錨點，即使起始發言退出近期 60 則仍可引用原文，沒有付費摘要或自行編造人物背景。

角色可以透過 `reply_to_message_id` 回覆之前批次的實際發言；同批只需指定 `recipient_ids`，`reply_to_index` 固定 null，程式會連結本批前面最近一則符合對象的發言。跨批參照必須是輸入已提供、同世界線的訊息，對象必須吻合，且優先於同批自動連結。UI 箭頭顯示接話對象，滑鼠移到訊息可看到回覆的訊息編號。常駐主線、十一個月、GLASSHOUSE、兄弟 AU 分別保存。

例如光先吐槽序，下一批序回嘴，REO 再補刀：這種前後接話可保存。這是互動示例，沒有把它寫成已發生的記憶或指定每批固定誰發言。確切自然度與母語口吻仍需正式模型實測。

關閉／重新開啟、異常中斷後，已提交的聊天與接話結構保留；備份／還原包含這些資料。重開後 AI 與自主聊天預設關閉，重新勾選後才可能付費。使用者確認清空該世界線聊天時才清除該世界線接話狀態。原人格、關係、重要事件與長期記憶沒有重置。

## NT$10／日與 NT$500／月

安靜聊天與單次安靜群聊成本測試共用每日估算 **NT$10**，也計入所有功能共用的每月估算 **NT$500**。兩個金額皆可自行調整。

每次 API 發出前，集中 `UsageLedger.reserve()` 原子檢查月內已記錄／預留費用加上本次保守費用是否足夠；涵蓋畫面分析、角色回覆、語音文字回覆、所有成本測試及安靜聊天。安靜請求再檢查當日額度。程序異常、取消或失敗但沒有完整用量時，保留可能費用；目前沒有背景付費記憶摘要或自動重試。

日額不足只暫停新的安靜聊天，文字／語音及已啟用的畫面分析仍可使用剩餘月額；次日依台灣時間恢復資格。月額不足停止所有新的 API 請求，已保存記憶保留，本機 VAD／辨識可繼續。金額是程式依設定價格與匯率的估算，平台實際帳單另看；使用者自行管理 OpenAI API 預付額度且已關閉自動儲值。公寓只發出已授權的對話請求，使用平台既有可用額度；不得付款、加值、開啟自動儲值或修改付款設定。每月 NT$500 只代表 API 使用上限，不代表充值金額；不足以預留下一次時停止並提示。

每天十小時，預設 6 分鐘冷卻的時間條件最多約 100 批，並非保證會呼叫或發言 100 批；每日／每月預算、互動、畫面事件與去重會減少次數。改成 3 分鐘冷卻也不能保證每天十小時持續熱聊。NT$10 × 30 日約 NT$300 只是安靜模式的每日上限累計，其他請求仍共用月額，可能更早停止。

## Windows 操作

1. 關閉舊版，把完整 0.4.5 ZIP 全部解壓到新資料夾，開啟其中 OurLittleDays.exe，確認版本。已下載 Whisper、聊天與 API Key 沿用。
2. 「API 安全設定／月預算」確認 gpt-4.1-mini、最大輸出 **2000**、月額 **500**、安靜每日額 **10**、冷卻 **6 分鐘**。舊版超過 2000 的設定會降到 2000；輸出上限變更需要重做原兩項成本測試，費用紀錄不清空。
3. 完成原「單次畫面分析」與「單次所選角色回覆」，勾「啟用文字 AI 回覆」。首次流程仍需一次畫面成本測試；完成後不必持續擷取。若停止擷取會暫停 AI，再重新勾文字 AI。
4. 先按 **「單次安靜群聊 · 測量費用」**。這次會付費，顯示實際輸入／輸出 tokens 與本機估算；已生成訊息保存。先核對效果與費用，再啟用排程。
5. 勾 **「啟用安靜時住戶自行聊天（會使用 API）」**，不必勾畫面自主陪伴。觀察本機檢查／冷卻提示、今日安靜費用及本月剩餘。關閉安靜選項可保留文字／語音回覆；「暫停所有 AI」則一起停止付費。

0.4.2 修正安靜群聊第一則訊息的無效同批接話參照：API 格式固定 reply_to_index=null，只需明確填接話對象。程式將同批較早且符合對象的最近一則訊息建立 SQLite reply_to 連結；第一則沒有較早發言，不建立虛構參照。跨批次的明確真實 ID 仍優先，世界線仍分開。沒有改寫發言、翻譯、人格或記憶，不新增 API 請求或自動重試。
