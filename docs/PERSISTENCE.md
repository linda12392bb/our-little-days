# 永久保存與恢復

使用者新增的正式需求已提前實作為 Phase 1 的資料底層。桌面控制與擷取流程保留；正式模型對話仍未啟用。

## 保存內容與位置

Windows 預設資料庫：`%LOCALAPPDATA%\OurLittleDays\apartment.sqlite3`。資料與安裝程式目錄分開，同一個使用者正常更新／重裝應用程式後，會繼續使用同一資料庫。可用 `--data-dir` 指定其他永久資料目錄。Linux 使用 `$XDG_DATA_HOME/our-little-days`，未設定則是 `~/.local/share/our-little-days`。

| 資料表 | 內容 |
|---|---|
| `characters` | 十三份完整角色 JSON，包括人格、外貌、語言、保留原文 |
| `worldlines` | 常駐主線與各 AU 識別 |
| `relationships` | 角色 ID＋世界線的獨立關係資料，不互相覆蓋 |
| `messages` | 發言者、原文、翻譯、時間、收件角色、回覆鏈、來源與世界線 |
| `events` | 重要事件摘要、文字證據、重要程度、時間與世界線 |
| `memories` | 公寓共用／角色長期記憶、來源事件、時間與世界線 |
| `settings` | 目前世界線與全域規則 |

初次啟動才匯入內建角色與原始規則。重新啟動不覆寫既有角色、不重置關係，也不重複新增歡迎訊息。內建 JSON 是初始種子；已有永久資料後，修改種子不會悄悄修改資料庫。自訂 `--characters` 只適用於新資料目錄，已存在的公寓會拒絕自動覆寫。

聊天每則以獨立 SQLite 交易提交，成功後才顯示與清除輸入。寫入失敗會提示並保留使用者輸入。使用者／角色／角色間訊息都使用相同儲存 API，支援收件角色和回覆鏈；目前 UI 保存使用者和標示為測試的角色氣泡，正式引擎尚未產生對話。

重要事件與長期記憶不依賴聊天列表，也不會因確認刪除聊天而消失。現在可在「記憶、事件與備份」手動記錄；後續 Phase 2–4 才加入自動事件分析、記憶萃取與模型上下文選取。**重新開啟可以看到已存記憶，尚未實作讓模型實際使用它生成回覆。**

## 暫停、關閉與異常退出

- 暫停只取消影格工作、清空預覽；不更動任何持久資料。
- 關閉主視窗會停止擷取計時器、取消工作並等待子程序清理；資料每次操作已提交，最後關閉資料庫。
- 重新啟動載入既有聊天、角色和記憶，擷取保持停止，須使用者重新開始。
- 使用 WAL 與 `synchronous=FULL`，已提交與未提交交易分開處理。
- 同一資料目錄以 Qt `QLockFile` 限制單一應用實例；異常退出後會依程序狀態辨識過期鎖。
- 發現資料庫損壞、格式不相容或版本較新，會提示、保留原檔並停止載入，不建立空白公寓取代它。

目前沒有 API 請求。Phase 2 導入 API 時，關閉與暫停的取消機制必須延伸到請求佇列與過期結果，不可把目前無請求當作已驗證 API 取消。

## 備份與還原

1. 開啟「記憶、事件與備份」，按「備份整間公寓」。
2. 選擇新的 `.sqlite3` 檔名；不覆蓋既有檔案。
3. 使用 SQLite backup API 取得一致快照，包含已提交的 WAL 資料；不是只複製一個可能正在寫入的主檔。
4. 還原時先檢查公寓識別、schema、完整性、外鍵、十三角色與目前世界線。
5. 使用者確認後停止擷取，先把目前資料另存至 `<資料目錄>/backups/before-restore-<時間>-<隨機碼>.sqlite3`。
6. 還原全部資料並刷新聊天室與角色；取消確認或無效備份不會取代目前資料。

正常更新／重裝不應刪除使用者資料目錄。若資料目錄被刪除、換電腦或磁碟故障，需使用另外保存的備份；「永久保存」不是磁碟故障時的無條件保證。備份包含私人聊天與角色記憶，未加密；可保存到自己信任的外部儲存位置。截圖、影片與 API Key 都不在此資料庫中。

「清空」預設回答為否，確認後僅刪目前世界線的聊天；角色關係、事件與長期記憶保留。底層 API 也要求確認參數，關係修改及還原不接受未確認呼叫。

## 已加入的恢復測試

`tests/test_storage.py`／`tests/test_persistent_ui.py` 實際涵蓋：

- 關閉資料庫、重新開啟，逐項核對角色編輯、關係、使用者／角色間訊息、事件及記憶。
- 關閉 Qt 主視窗、再開新視窗，核對舊訊息與出場狀態，歡迎訊息不重複。
- 在獨立子程序寫入已提交資料、開啟未提交交易，以 `os._exit(19)` 異常退出；重新開啟確認已提交內容恢復、未提交內容回滾及完整性通過。
- 不同世界線記憶隔離；拒絕跨世界線事件引用。
- 從含 WAL 資料的活躍資料庫備份，還原後核對所有資料、還原前安全備份與 UI 重載。
- 取消刪除、未確認還原／關係修改、不相容／損壞備份與磁碟寫入失敗。

這些測試在目前 Linux 雲端實際執行；真實 Windows 擷取與 native GUI 操作仍須依 [ACCEPTANCE.md](ACCEPTANCE.md) 在 Windows 驗收。沒有模擬硬碟硬體故障、停電或完整 Windows 重裝。

## Phase 2/3 費用與憑證

原有 apartment.sqlite3 七表保持相容。AI 訊息（含接話關聯）與畫面事件原子提交；模型不自動改變人格或戀愛關係。另以 api-usage.sqlite3 記錄費用與設定，聊天還原不會倒退月用量；本機設定可備份及合併還原用量。openai-key.dpapi 為 Windows 帳號加密憑證，不包含於聊天／用量備份。關閉與異常中斷後 AI 預設關閉，可能已送出的請求費用仍保留。詳見 [PHASE2_3.md](PHASE2_3.md)。
