# 一、專案目標

請開發一款 Windows 桌面應用程式，讓使用者可以指定電腦上某個正在運行的視窗，並讓十三個具有獨立人格設定的虛擬陪伴聲道，根據該視窗正在發生的事情，自主在另一個獨立聊天室中留言。

本程式不是普通的問答聊天機器人，也不是必須由使用者發送訊息才會觸發回覆的聊天室。

**最核心的功能：使用者完全不打字時，十三聲道仍能透過視窗事件，自主決定是否發言、由誰發言、是否互相接話。**

使用情境包含：

- 玩 Steam 或其他 PC 遊戲時，十三聲道可以觀看指定遊戲視窗並反應。
- 看動畫、影片時，十三聲道可以對已辨識的場景與台詞聊天。
- 使用繪圖軟體時，十三聲道可以觀察可見的工作進度。
- 使用者可以隨時加入聊天、提問或指定聲道回應。

不需要使用者持續提供時間碼、截圖或文字說明。

# 二、桌面介面規格

## 2.1 獨立聊天室

聊天室必須是一個獨立 Windows 視窗，不得直接覆蓋或修改目標應用程式的畫面。

必備功能：

1. 自由拖動視窗。
2. 自由調整視窗大小。
3. 可切換「永遠置頂」。
4. 可最小化與還原。
5. 可捲動歷史訊息。
6. 新訊息自動捲動；使用者正在閱讀舊訊息時，不應強制跳到底部。
7. 支援繁體中文、日文、英文。
8. 提供使用者輸入框及送出功能。
9. 提供目前監看視窗、擷取狀態及 API 狀態。
10. 可一鍵暫停／恢復監看與自動留言。

介面視覺方向：

- 奶油日記
- 柔和莓果色系
- 溫暖公寓生活感
- 圓角文字氣泡
- 各聲道專屬顏色
- 簡潔、可讀、不干擾遊戲

主標題：月色不打烊｜公寓還是一樣很吵

副標題：OUR LITTLE DAYS · 2026

# 三、指定視窗擷取系統

## 3.1 視窗選擇

程式必須提供目前可選擇的 Windows 應用程式視窗清單。

使用者自行選擇目標。

例如：

- 遊戲視窗
- 瀏覽器視窗
- 影片播放器
- 繪圖軟體

選定後鎖定該視窗，不因使用者切換前景程式而擅自改變監看對象。

## 3.2 畫面擷取

建議優先研究 Windows Graphics Capture 等 Windows 原生視窗擷取機制。

需求：

- 僅擷取使用者明確選定的視窗。
- 支援可調整的擷取頻率。
- 避免每幀都呼叫模型 API。
- 優先利用畫面變化偵測降低成本。
- 視窗關閉或擷取失敗時顯示狀態。
- 不自動切換為整個桌面擷取。
- 不繞過 DRM、反作弊或其他存取保護。
- 受保護影片無法擷取時，明確提示限制。

若遊戲使用獨佔全螢幕或特殊渲染方式，可能需要使用者切換無邊框視窗模式。

## 3.3 資料隱私

畫面擷取只在使用者啟動監看後運行。

預設：

- 不永久保存原始截圖。
- 不錄製整段影片。
- 不監看未選定的視窗。
- 不收集鍵盤輸入或密碼。
- 不自動上傳畫面到其他服務。
- 傳送畫面給模型 API 前，明確告知使用者。
- 提供敏感資訊暫停與擷取預覽功能。

如需儲存聊天歷史，使用本機資料庫，並提供刪除功能。

# 四、畫面理解與事件判斷

建立獨立的「視窗觀察引擎」。

流程：

1. 定期取得指定視窗畫面。
2. 比較畫面變化。
3. 必要時擷取代表性影格。
4. 使用具備視覺理解能力的模型分析。
5. 建立近期事件摘要。
6. 判斷是否存在值得回應的新事件。
7. 將事件傳送至十三聲道反應引擎。

可辨識的事件範例：

**遊戲：**

- 戰鬥開始
- 角色死亡
- 勝利或失敗
- Boss 階段變化
- 劇情對話
- 選項出現
- 裝備或道具取得
- 明顯的搞笑畫面

**動畫與影片：**

- 角色出場
- 可讀取的字幕內容
- 明顯的場景變化
- 人物互動
- 重要視覺事件

**繪圖：**

- 畫布明顯變化
- 新增主要元素
- 顏色或構圖調整

事件判斷不得將推測描述為已確認事實。

若畫面資訊不足，聲道可以表達疑問、猜測，或選擇不發言。

### 4.1 事件去重

同一事件不得因連續擷取而重複觸發相同反應。

例如遊戲死亡畫面停留十秒，不應每次擷取都重新產生一輪「妳死了」的對話。

### 4.2 短期上下文

保留最近事件摘要、聊天訊息及重要狀態，讓聲道能理解事件的先後關係。

不要每次分析都當作全新畫面。

# 五、十三聲道自主對話引擎

這是本專案最重要的系統。

必須支援十三個獨立設定的聲道，但不要求同時執行十三個模型實例。

建議由中央協調器負責：

- 決定是否需要發言。
- 選擇一至數位聲道。
- 控制發言順序。
- 維持每個聲道的人格與語言設定。
- 判斷是否需要互相接話。
- 防止無意義的重複留言。
- 避免每次十三人輪流發言。

## 5.1 自主發言

**不需要使用者輸入訊息也能觸發。**

範例：

使用者正在遊戲中遭遇 Boss 第二階段。

系統辨識到新事件。

💡光：幹！！！怎麼還有第二階段！！！！

📖聖護：まだ終わっていなかったようだね。
（看來還沒有結束呢。）

系統可以產生這樣的反應，但應以實際觀察結果為依據。

## 5.2 發言頻率

提供三種模式：

- 安靜：只對重大事件反應。
- 一般：適度聊天，允許自然接話。
- 熱鬧：增加反應與聲道間互動。

同時提供：

- 最短發言間隔。
- 單次事件最多回應人數。
- 每分鐘訊息上限。
- 防洗版機制。
- 手動靜音／暫停。

即使在熱鬧模式，也不應為了達成發言數量而製造無意義對話。

## 5.3 聲道之間可以聊天

允許：

- 回應畫面事件。
- 回應使用者。
- 回應其他聲道。
- 開玩笑、吐槽、討論、意見不同。
- 保持沉默。

禁止強制每次所有人都回覆。

## 5.4 使用者加入聊天

使用者可直接輸入訊息，例如：

- 你們覺得我要選哪個？
- 剛剛那個也太好笑了吧 XDDDD
- 聖護，你怎麼看？
- 先不要劇透！
- 你們安靜一點 XDDDD

系統需同時參考最近的畫面事件與聊天上下文。

使用者的訊息應優先於一般自動吐槽處理。

# 十三、最終驗收情境

使用者在 Windows 電腦上：

1. 啟動「月色不打烊」。
2. 從視窗清單中選擇正在運行的遊戲。
3. 將十三聲道聊天室拖到遊戲旁邊。
4. 開啟或關閉永遠置頂。
5. 點擊「開始陪伴」。
6. 正常進行遊戲，不需要打字。
7. 遊戲出現新的明顯事件。
8. 程式取得可用畫面並辨識事件。
9. 十三聲道協調器決定是否有人要說話。
10. 一至數位聲道自動產生文字氣泡。
11. 其他聲道可以自然接話，也可以保持沉默。
12. 使用者隨時輸入問題，聲道可以回答。
13. 使用者點擊暫停，立即停止新的擷取與自動留言。

**成功標準不是十三個人一直講話，而是讓使用者感覺自己在正常玩遊戲、看動畫或創作時，旁邊有一個會觀察、會反應、會互相聊天，而且不需要自己一直照顧的公寓聊天室。**

請以這個目標為最高開發優先順序。
